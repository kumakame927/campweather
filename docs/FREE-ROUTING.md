# アクセス比較：無料で実現できる範囲と制約

確認日：2026-10-31（日本時間）。**Google Cloudの無料トライアル登録・課金設定・有料API呼び出しは行わない。新しい経路サービスへのアカウント登録も今回行っていない。**

## 結論

- 出発地点の検索・保存・変更、現在地の明示的な許可取得、車／公共交通切替、日時選択、全キャンプ場の時間・距離一覧、時間順／撤収日の雨順の表示は、Google APIなしで開発・テストできる。作業ブランチで実装・テスト済み。
- 実際の車・徒歩の経路時間・距離は、OSRM系やopenrouteservice等の無料サービスを利用できる可能性がある。公開アプリには利用枠・帰属・データライセンス・個人情報送信の条件を適用する必要がある。
- 日本の鉄道・バスを含む日時指定の経路比較は別問題。今回調べた候補では、**日本の車・鉄道・バス・徒歩を全てカバーし、公開アプリで継続無料利用できるホスト済みAPIは確認できなかった**。「存在しない」と断定するものではない。
- 公共交通オープンデータを自分の経路エンジンへ入れる方法はあるが、無料データ／オープンソースと、無料で安定運用できる公開サーバーは同じではない。

### openrouteserviceの公開条件

現行の公式プランは「Free to use for everyone」。取得結果はCC-BY-SA 4.0とされ、`© openrouteservice by HeiGIT | Data from OpenStreetMap` 等の帰属が必要。公開画面での表示、取得結果の二次利用・再配布は適用ライセンスに従う。無料APIの利用枠を複数アカウントで回避しない。規約にはサービス変更・停止や品質保証がない旨もある。

個人データ送信を禁止する規約の表現があるため、現在地や自宅に結び付く座標をどのように扱えるかは提供者へ確認する。APIキーと帰属だけで全ての公開・プライバシー要件を満たす、と判断しない。

無料Standardの確認値：

- Matrix V2：日500 / 分40
- Directions V2：日2,000 / 分40
- 日次枠は単純な日本時間0時リセットではなく、初回リクエストからの24時間窓。分次枠は連続60秒の窓。
- 実際の残量は管理画面とレート制限ヘッダーで確認する。個別エンドポイントの行列サイズ等にも制限がある。

### OSRM公開サーバーの位置付け

FOSSGISの公開サーバーは小規模な試験候補にはなるが、無制限の無料インフラではない。1秒1件は各ブラウザだけの制限ではなく、アプリ全体の呼び出し設計で守る。規約に従って識別情報・帰属・地図修正リンクを付ける。経路要求は提供者のログに残るとの説明があるので、出発地のプライバシーも説明する。

旧OSRM Wikiの条件だけに依存せず、実際に利用する運営者の現行ポリシーを優先する。運用が大きくなる場合は、自前運用または利用条件が明確なサービスへ移す必要がある。

### 公共交通データの公開利用

ODPT基本ライセンスは、そのライセンスが適用されたデータでアプリ等を作り、一般利用者へ公開することを認める。ただし事業者の個別条件・ガイドラインが追加される場合がある。ガイドラインには、出典、正確性を保証しない旨、開発者の問い合わせ先、動的データの更新時刻、更新への対応等の要求がある。

期間限定ライセンスは基本ライセンスと同じではない。キャンペーンで取得したデータを期限後も公開利用できると仮定しない。GTFS-JPというフォーマット名自体が、データの無料公開・再配布許可を意味するわけでもない。

対象の3キャンプ場へ行ける鉄道・バス、最終徒歩区間、該当日のダイヤを用意できて初めて比較可能。データがない区間を、直線距離や独自の平均速度で補って公共交通の所要時間と表示しない。

## 現時点で確認できなかった候補

- 駅すぱあとAPI：旧フリープランURLは現行のスタンダードプランのドキュメントへ転送され、公式画面では90日無料トライアルを確認した。恒久無料の公開用経路APIと確認できないため、今回の無料継続運用案には採用しない。
- NAVITIME API：車・公共交通に対応するが、今回確認できた公式資料から恒久無料での公開アプリ利用条件までは確定できない。契約せず候補保留とする。
- Valhalla：オープンソースで、GTFSを用いた公共交通の構成候補。ただし公開デモで日本の対象区間の鉄道・バスのダイヤが提供されることと、公開アプリ向けの継続無料条件は確認できず、即利用可能な無料APIとは扱わない。
- Yahoo!・Google等の一般向け経路ページをスクレイピングして独自API化する方法は採らない。Webで見られることとAPIとして再利用できることは別。

## 今進められる範囲

1. UI・出発地点の保存・移動手段切替・日時・時間/雨順・経路取得不可の状態を仕上げる：作業ブランチで実装済み。
2. 時間・距離の並べ替えや欠落経路は、`tests/` 内の隔離テスト応答で確認する。本番コードにサンプル結果を埋め込まない。
3. 実APIがない本番向け画面は「経路情報を取得できません」とし、時間・距離は未取得／取得不可にする。
4. 次の実サービス候補は**車・徒歩を先行**して検討する。openrouteserviceの無料キー・公開/個人データ条件を確認する案と、OSRM公開デモを小規模な試験だけに使う案がある。どちらも今回まだ登録・接続していない。
5. 公共交通は、継続利用できるデータと計算基盤が決まるまでは取得不可を維持する。必要なら対象地域・対象事業者を絞ったOTPのローカル実験を別工程で検討する。

## コード・ブランチの状態

- アクセス実装はローカルの `feat/access-comparison` に保持する。mainはスマホ修正の`6f005da`のまま変更しない。
- Google用サーバーアダプターは将来用の無効な状態で残している。キー・有効化フラグ等がない場合、Googleへのネットワーク呼び出しは発生しない。Google Cloudの登録・無料トライアル・課金設定は今回の作業計画に含めない。
- 現在の経路APIは未設定。車/公共交通の実際の時間・距離が取得できると装わない。
- 保存したキャンプ場・日程・出発地は保持し、天気取得・撤収日の降水確率を最優先にする既存ランキングを変更しない。
