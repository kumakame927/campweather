# 気象庁の参考予報

確認日：2026-10-31。Open-Meteoを主予報とし、気象庁は区域全体の参考情報として別欄に表示する。気象庁のデータをおすすめ順位に混ぜない。APIキー・Google Cloud・有料データ契約は不要。Vercelの既存利用枠内のFunction実行・転送は発生するが、プラン変更や課金有効化は行わない。

## 取得方法・表示項目

気象庁ホームページが使用する公開JSONを、Vercel FunctionがHTTPSで取得する。

- `https://www.jma.go.jp/bosai/forecast/data/forecast/{office}.json`
- 府県天気予報：その一次細分区域の天気、6時間ごとの降水確率、予報発表日時。
- 週間予報：一致する一次細分区域、または府県全体の区域コードに限って、天気と気象庁発表の日単位の降水確率を表示。使った週間予報の区域名をそのまま表示する。
- 府県予報は通常5時・11時・17時に発表し、急変時は随時修正。今日・明日・明後日の天気、明日までの6時間降水確率が基本。週間予報は翌日から7日先まで、通常11時ごろ・17時ごろに発表。
- 数値が空文字・欠測なら「発表なし」。時間帯別確率の合計・平均・最大から独自の日確率を作らない。対象時間帯は日本時間の `00–06時` 等を表示する。
- 選択日の予報がない場合は対象期間外と表示する。日付は存在しても該当区域のデータがない場合は「この区域に対応する予報を確認できません」と区別する。
- 週間予報の特殊・季節区分を自動対応できない場合は、別区域の予報を推測して埋めない。気象庁ホームページへのリンクを付ける。
- 気象庁の気温は代表観測地点のものなので、今回キャンプ場の気温としては転用しない。気温・風速の比較は従来どおりOpen-Meteoを使う。

公開JSONはバージョン保証された開発者APIではなく、仕様・URLが変更される可能性がある。形式・時刻・確率を検証し、36時間より古い発表、未来の不正な発表時刻、未知の時間軸等は表示しない。失敗時は参考欄だけにエラーを表示し、Open-Meteoの取得・表示は継続する。

## 区域判定

公式データのスナップショットを `server/data/` に保存し、サーバー側でだけ使う。位置検索APIを追加せず、登録済みの施設座標・住所を使う。

- 区域の階層・名称：`https://www.jma.go.jp/bosai/common/const/area.json`
- 一次細分区域ポリゴン：`https://www.jma.go.jp/bosai/common/const/geojson/class10s.json`
- 天気コードの日本語表記：`https://www.jma.go.jp/bosai/forecast/` 内の公式 `TELOPS` 表。
- ポリゴンの区域コードから `area.json` の一次細分区域名・発表官署を引く。ポリゴンのproperties.nameは府県名の場合があるので、区域名として流用しない。
- 1区域の内部にあることが確認できた地点だけを使う。海上・未対応・重複区域は未確定とする。
- 地図用ポリゴンは簡略化されているため、境界から1km以内は、公式階層で分割されていない市町村の「都道府県＋市町村」住所と座標の区域が一致した場合だけ対応する。住所と座標に矛盾があれば未確定。住所だけで座標を上書きしない。
- 市町村名の部分一致や地域の中心点・最寄り地点から他区域を選ばない。分割市町村・英語のみの住所・県境/海岸の地点等では、正しい地点でも参考予報を表示できない場合がある。

初期3施設の確認結果：

| 施設 | 府県予報区 | 一次細分区域 |
| --- | --- | --- |
| ふもとっぱら | 静岡県 `220000` | 東部 `220030` |
| 伊豆かくれオートキャンプ場 | 静岡県 `220000` | 伊豆 `220020`（伊豆市の住所でも照合） |
| ニコニコキャンプ | 茨城県 `080000` | 北部 `080010` |

例：静岡県の週間予報は「静岡県」と明記し、東部・伊豆のピンポイント週間予報と表示しない。

区域変更への対応では、上記公式3資料を再取得して `jma-catalog.json`（offices/class10s/分割のないclass20s）、`jma-areas.geojson`、`jma-weather-codes.json` を同時に更新し、区域テストを通す。データの出典と加工内容はこの文書と画面の参考欄・フッターに表示する。

## 発表日時とデータ取得日時

- 気象庁の `reportDatetime` を「予報発表日時」として日本時間で表示する。短期と週間で発表時刻が違う場合も、それぞれ表示する。
- サーバーが実際に取得した時刻を「気象庁データ取得日時」として表示する。キャッシュを返す時刻で書き換えない。
- Open-Meteoの現在のForecast APIのJSONと[公式OpenAPI定義](https://github.com/open-meteo/open-meteo/blob/main/openapi/forecast.yml)には、今回の予報値に対応するモデルの更新・初期化日時がない。`generationtime_ms` は処理時間で、更新時刻ではない。
- `best_match` は複数モデルを使い得るため、他のモデル情報から更新時刻を推定しない。Open-Meteoは応答受信時刻を「Open-Meteo データ取得日時」と表示する。

## キャッシュと外部アクセス

- 参考欄は初期状態で閉じ、開いたときだけ取得する。
- `/api/jma-area`：座標・住所から判定するサーバー処理。気象庁への通信なし。住所・座標は気象庁へ送らない。ブラウザのprivateキャッシュは24時間。Vercelのアクセスログにリクエストが残る場合はある。
- `/api/jma-forecast?office=220000`：発表官署単位で共有。任意のURLは受け付けない。全日程を一度に取得するので、日程変更のたびに外部APIを呼ばない。
- フロント側は同一官署の処理中リクエスト・結果を10分間共有する。サーバーも官署単位で10分キャッシュし、同時リクエストを統合する。
- Vercel CDNにも最大10分の共有キャッシュ。メモリキャッシュの取得日時から残り有効時間を計算し、CDNに載せ直して10分を延長しない。ブラウザは最大60秒。
- サーバーでは失敗後60秒間、同じ官署への再通信を抑える。期限切れの結果を通信失敗時の代替予報としては返さない。
- サーバーレスのメモリキャッシュはインスタンス間では共有されない。CDNと組み合わせるが、全インスタンスで厳密に「10分に1回」を保証するものではない。大規模運用時は共有ストレージ等を別途検討する。
- 仕様変更・タイムアウト・HTTPエラー・不明な区域には独立したメッセージを表示する。静的なGitHub Pages単体ではFunctionが動かないため、この参考機能にはVercelが必要。

## 検証

- `npm test`：既存の予報・順位・データ保持19項目、気象庁の区域・6時間/日確率・時刻・欠測/対象期間・キャッシュ・失敗/無効入力の12項目。
- `npm run test:jma`：隔離したテスト応答でChromium/WebKitの表示・折りたたみ・日程変更・エラー独立性・5画面幅を確認。
- `node tests/jma-browser.js --real`：実際のOpen-Meteoと気象庁を使うローカルプレビューのブラウザ確認。テストデータへの差し替えなし。
- `npm run test:trip` / `npm run test:layout`：既存の日程・追加/削除/保存・地図・スマートフォン入力を確認。
- `npm run build` / `npm run build:vercel`：ビルド。気象庁JSONとテスト用予報データはフロントのdistに含めない。

ブラウザ確認では開発サーバーを別途起動する。`CAMP_PREVIEW_URL`、`CHROMIUM_EXECUTABLE_PATH`、`WEBKIT_EXECUTABLE_PATH`で確認先・実行環境を指定できる。
