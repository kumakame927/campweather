# キャンプ場一覧検索とお気に入り・天気比較

## 取得方法・費用と制約

関東7都県＋山梨・長野・静岡の10都県について、OpenStreetMapの `tourism=camp_site` / `tourism=caravan_site` で名前のある施設をOverpass APIから抽出する。公開Nominatimは一括収集に使わない。利用者の施設名検索時にもOverpass・Nominatimは呼ばず、取得済み一覧をブラウザ内で検索する。

初回は実データ1,407施設、約329KBのJSON。電話番号・連絡先・施設の全タグ等を取得一覧へ持ち込まず、名前・別名・住所タグ・座標・OSM識別子へ絞る。OSM未登録施設は含まれず、営業・予約可否は保証しない。私有/立入不可、廃止タグの施設は除外する。住所検索・地図指定による登録を残す。

新規アカウント・APIキー・有料APIは不要。このリポジトリは公開されており、標準Linux runnerのGitHub Actionsで定期処理を行う。既存VercelのFunction/CDNを再利用し、課金設定や有料プランへの切替は行わない。公開APIには可用性保証がなく、既存サービスの利用枠を超える大規模運用を無制限無料とするものではない。

確認した公式資料：

- [Overpass公開インスタンスのリソース・制限](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)：目安は1日約10,000リクエスト・約1GB未満で、空きスロット・実行時間・メモリを共有。利用枠は成功を保証しない。
- [OSMの著作権・ODbL](https://www.openstreetmap.org/copyright)：出典と共有条件を適用。
- [Nominatimポリシー](https://operations.osmfoundation.org/policies/nominatim/)：大量取得を行わず、既存の明示的な住所/地図検索・1.1秒以上の間隔・成功結果のキャッシュを維持。
- [GitHubスケジュール実行](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)：デフォルトブランチにworkflowが必要。負荷による遅延や、リポジトリの非活動等による無効化があり得る。

## 自動更新

`.github/workflows/update-camp-catalog.yml` が毎日UTC 00:17（日本時間09:17）に更新要否を調べる。前回成功から7日未満ならAPIへ接続せず終了する。7日以上なら `scripts/update-camp-catalog.mjs` で更新し、失敗した日は次の実行で再試行する。

- 都県境界のISOコード・admin_level=4を指定し、10都県を直列取得する。都県ごとに通常1件、成功後5秒待機。通常は週10リクエスト程度。
- 同時の大量問い合わせ、全世界の分割ダウンロード、制限回避の別エンドポイント巡回は行わない。
- 混雑や429/502等は30秒・60秒等の待機で最大3回まで。提供元のRetry-Afterが長い場合は更新を中止して次回へ回す。
- 全10都県の成功、JSON形式・OSM更新日時・施設情報を検証してから一時ファイルをrenameする。remark/部分的なエラー、著しい施設数減少では置き換えず、既存一覧を保持する。
- 自動コミット対象は `public/data/campgrounds.json` だけ。GITHUB_TOKENのcontents:writeをworkflowに明記し、APIキーや追加secretは使わない。
- 権限・ブランチ保護・GitHub側のスケジュール無効化が変わった場合は管理者の対応が必要。通常の施設単位の更新に手作業は不要。

Vercelの `/api/camp-catalog` は、固定の公開GitHub raw URLから最新のコミット済み一覧を取得する。自動コミットがVercelビルドを起動するかに依存しない。Vercel CDNは通常1時間、サーバーメモリは15分、ブラウザHTTPは5分、同じ画面内は1時間キャッシュし、施設ごとの通信を作らない。処理中のリクエストも共有する。

GitHubへの取得失敗時は同梱・直前の実一覧へフォールバックし、更新日と前回の一覧である旨を表示する。14日を超えて古くなった場合も更新遅延を示す。通信失敗を0件の検索結果と混同しない。静的環境では同梱JSONを使うため、最新反映には静的ビルド更新が必要。

nodeはOSM登録点、way/relationはOverpassの区域中心座標を使用する。区域中心は入口やピンポイント施設位置とは限らないため、確認画面で明記し、地図で位置を調整できる。住所タグがない施設は都県名と「市町村・番地はOSM未記載」と表示し、逆ジオコーディングを大量実行したり、住所を推測したりしない。

## あいまい検索

全半角・空白・ひらがな/カタカナ・「キャンプ村」「キャンプ場」等を正規化し、OSMの主名称・別名を部分一致検索する。結果は一致度順で最大20件。文字入力中のAPI通信は行わない。漢字の読みはOSMの別名・読みタグがある場合だけ利用し、未知の読みを作らない。

実際のOSM node/4105493143 は「菖蒲ヶ浜キャンプ場」（栃木県日光市中宮祠2485、36.7515948 / 139.4509786）。「菖蒲ヶ浜キャンプ村」「菖蒲ヶ浜」「菖蒲」の3通りすべてで候補になることを実データとテストで確認する。

## お気に入りと比較の独立性

- UI名は「お気に入りキャンプ場」。お気に入り登録/解除と比較への追加/除外は独立操作。
- 新規登録の確認画面には「比較に追加」と「お気に入りに登録」を分けて表示。お気に入りだけの新規登録では天気を取得しない。
- 比較カードの「比較から外す」はお気に入りを変更しない。☆/★によるお気に入り解除は比較カードを消さない。
- 一覧からワンタップで比較に追加できる。比較中の施設だけがOpen-Meteo/JMAの対象。
- 比較対象が増減した際は、同じ日程・位置の取得済み予報を30分以内なら再利用し、変わっていない施設への余分な天気取得を抑える。
- お気に入りでない登録情報は一覧内の「お気に入り以外の登録」に残し、再追加・お気に入り登録・完全削除ができる。
- 完全削除は確認ダイアログを出し、登録情報と両状態を削除する。
- OSM識別子、地図調整前のキャンプ場OSM参照、同一座標、近接する同一正規化名で重複を防ぐ。同じ名前でも遠方の施設はまとめない。重複再追加は、登録済みの名前・調整済み位置を勝手に上書きしない。

## 永続化と移行・バックアップ

既存 `camp-weather-camps-v2` のcamp配列は登録施設全体を保持する。従来のv1読み込みとv2の0件データを維持する。比較とお気に入りは新しい独立キーに保存する。

- `camp-weather-comparison-v1`：`{version:1, ids:[...]}`
- `camp-weather-favorites-v1`：`{version:1, ids:[...]}`

旧データでキーがない場合は、その時点の全登録施設をお気に入り・比較中として移行する。移行だけでは既存のcamp配列を書き換えない。既に比較キーがある場合は、その状態を維持する。空の選択配列は0件のまま復元する。

保存時は複数キーの書き込み失敗を検出し、書き換えたキーを元に戻す。バックアップは全登録施設・両状態を含め、旧形式のバックアップも全件お気に入り/比較中として取り込む。日程・PWA・既存の検索キャッシュ・アクセス比較開発ブランチは維持する。

## テスト

`npm test` に一覧正規化・取得制約・不完全応答・キャッシュ・移行・独立状態・重複・バックアップの16項目を追加。

- `npm run test:library`：Chromium/WebKitで状態を操作し、実際の天気リクエスト件数を確認する隔離テスト。
- `node tests/library-live.js`：実際の一覧・Open-Meteo・JMAで、指定3検索・お気に入りだけなら未取得・比較追加時のみ取得・再読込保持を確認。
- 既存の住所/地図登録・日程・ランキング・JMA・PWA・スマートフォン配置も回帰確認。
- `node scripts/update-camp-catalog.mjs --scheduled`：7日以内の一覧なら外部APIを呼ばず終了する運用確認。
