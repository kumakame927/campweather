# 晴れキャン — キャンプ日程の天気比較

ふもとっぱら・伊豆かくれオートキャンプ場・ニコニコキャンプを初期一覧に持つ、スマートフォン向けの天気比較アプリです。既存の Vite / JavaScript 構成を使用し、バックエンドや API キーを必要としません。

## 起動・検証

Node.js 20.19+ または 22.12+ を使用します。

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run preview
```

`npm test` は日付・順位・欠測・検索結果の検証など19項目を実行します。テスト用データはテストファイルにのみ置き、本番アプリにデモ予報を表示する経路はありません。

ソースを静的プレビューする場合は、リポジトリのルートをHTTPサーバーで配信します（例：`python3 -m http.server 4174`）。HTMLからCSSを、相対パスでJavaScriptを読み込むため、Viteを通さない静的配信やサブディレクトリ配信でも操作できます。`file://` での直接表示は使用しません。

ブラウザの回帰テストは次の手順で実行できます。

```sh
npx playwright install chromium
npm run build
npm run test:browser
npm run test:browser -- --live
```

システムのChromiumを使う場合は `CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium` を指定します。通常のブラウザテストは隔離したテスト応答、`--live` は実際のNominatimとOpen-Meteoを利用します。両方ともソースの静的プレビューとビルド済み成果物をHTTPで配信し、追加ボタン→ふもとっぱら検索→候補選択→登録→予報表示→再読み込み・保持をブラウザで操作します。スクリーンショットはGit管理外の `test-results/` に保存します。

今回再現した不具合は、JavaScript内のCSS importをVite未使用の配信で実行しようとしたためのMIME型エラーです。CSSをHTMLのlink要素から読み込むことで修正しています。モジュール起動失敗時にはエラーを画面に表示します。

## 初期キャンプ場の場所

ふもとっぱらは、[公式サイトの住所（静岡県富士宮市麓156）](https://fumotoppara.net/) と [OpenStreetMap の施設情報](https://www.openstreetmap.org/way/640260125) を照合し、座標 `35.3985153, 138.5659069` を登録しています（2026-10-31確認）。初回表示から予報を取得します。

伊豆かくれオートキャンプ場は、利用者指定の住所「静岡県伊豆市八木沢2929-5」と[楽天トラベルキャンプの施設情報](https://camp.travel.rakuten.co.jp/properties/1411) から正式表記「伊豆隠れオートキャンプ場」を確認し、その名称の [OSM施設データ](https://www.openstreetmap.org/node/14285784581) の座標 `34.8888729, 138.7690670` を登録しています。「八木沢」全体の中心点は使っていません。場所の再検索には正式表記を使用します。

ニコニコキャンプは、利用者が茨城県笠間市上郷の「にこにこキャンプ」であることを確認済みです。[OSM施設データ](https://www.openstreetmap.org/node/14286833431) の座標 `36.3141326, 140.2297206` を登録しています。以上の確認日は2026-10-31です。初期3施設は初回表示から自動で予報を取得します。

位置の変更はカードの「場所を変更」から行えます。住所・座標を確認できない施設に、推測の位置を登録しません。

「キャンプ場を追加」も同じ手順です。候補を選んだだけでは登録せず、確認欄の登録ボタンを押した時点で保存します。同名施設を自動選択しません。検索結果がない場合は都道府県や市町村、正式名称を加えてください。地図に未登録の施設は検索できない場合があります。

初期施設など登録済みの場所を追加画面から確認した場合は二重登録せず、その施設の位置を保存して予報を再取得します。

## 予報と比較

- [Open-Meteo Forecast API](https://open-meteo.com/en/docs) から施設の座標で実際の予報を取得します。
- 開始日をカレンダーから選び、日帰り・1泊2日・2泊3日を指定できます。初期表示は日本時間で直近の土日です。土曜は当日を含み、日曜には次の週末へ切り替わります。「直近の土日」で初期日程に戻せます。手動で選んだ日程は自動で変更しません。
- 予報範囲は日本時間の今日から15日後まで（計16日間）です。過去の日程や最終日が範囲を超える日程は案内を表示し、APIリクエストとランキング計算を行いません。提供元で予報が欠測する場合も、その旨を表示します。
- 選択日程は `camp-weather-trip-v1` に保存します。
- 天気（WMO weather code）、1日の最大降水確率、最高・最低気温、1日の最大風速（m/s）を日付ごとの列で比較表示します。
- 並び順は **最終日（撤収日・日帰りでは当日）の最大降水確率 → 日程中の最大風速 → 最終日以外の最大降水確率** の昇順です。特に1泊2日は撤収日の降水確率を最優先にします。同条件の候補はすべて表示し、カードは名前順に並べます。
- 気温は比較用に表示しますが、好みの温度を仮定した点数付けはしません。
- 選択日程の全日分の必要な値がそろった施設だけでおすすめを選びます。1施設のみ取得できた場合は「比較できていない」と明示します。
- 取得失敗・タイムアウト・利用制限・欠測はその旨を表示し、`0%` や晴れに置き換えません。未取得の予報を実データとして表示しません。
- 初回表示・場所の登録後に自動取得し、表示中は30分ごとに更新します。手動更新もできます。同時リクエストは3件までです。古いリクエストは更新時に中止します。
- 取得時刻は API 応答を受信した日本時間です。モデル計算時刻ではありません。

## 保存と検索サービス

施設の名前、確認した住所・緯度経度、出典を `localStorage` の `camp-weather-camps-v2` にバージョン付きリストとして保存します。旧 `camp-weather-camps-v1` の登録済みデータを引き継ぎ、旧キーはバックアップとして消しません。新形式では保存済みリストをそのまま復元し、初期施設を勝手に追加しません。保存できない場合は登録せず、エラーを表示します。端末間の同期はありません。旧一覧アプリのお気に入り・メモの保存領域は消去していませんが、今回の比較画面からは操作しません。

場所検索には無料の [Nominatim](https://nominatim.org/) を使用します。日本国内の候補を検索し、検索ボタンを押した場合のみリクエストします。オートコンプリートや初期施設の一括自動検索は行いません。同一ブラウザ内で1.1秒以上の間隔を空け、結果を24時間キャッシュします。Web Locks に対応するブラウザでは別タブの検索も直列化します。住所と検索情報の出典として OpenStreetMap の帰属表示を行っています。

無料公開 API には利用制限があります。Open-Meteo の無料 API は非商用利用向けです。一般公開・利用増加の際は各サービスの最新規約をご確認ください。Nominatim の公共サーバーはアプリ全体での負荷にも制約があるため、多数の利用者を対象にする場合は利用規約に適合する別のサービスや自前の検索基盤が必要です。

## GitHub Pages

`npm run build` の生成先 `dist/` をそのまま静的配信できます。`vite.config.js` の `base: './'` により `https://<user>.github.io/<repository>/` のようなサブディレクトリでも JS / CSS / favicon を読み込めます。クライアント側のパスルーティングや秘密鍵はありません。

GitHub Pages へ反映する際は、GitHub Actions などで `npm ci` → `npm run build` を実行し、`dist/` を Pages の成果物として配信します。今回の作業では push・デプロイは行っていません。

## ネットワーク

実行するブラウザから次の HTTPS 接続が必要です。

- `api.open-meteo.com`：予報
- `nominatim.openstreetmap.org`：施設名による場所検索
- `www.openstreetmap.org`：外部タブでの地図表示・帰属情報

開発クラウド環境でAPIへの接続が拒否される場合は、環境側の許可設定が必要です。アプリ内にプロキシや疑似データを入れて制限を回避しません。


## プレビューのAPI通信とエラー調査

`npm run dev` のプレビューでは `/api/open-meteo/v1/forecast` と `/api/nominatim/search` を同一オリジンで呼びます。Vite が固定の外部 API にリレーし、環境の `HTTPS_PROXY` と TLS 検証を維持します。ブラウザから外部 API への直接接続を制限するプレビュー向けの対策です。GitHub Pages 向けの静的ビルドでは外部 API に直接接続します。静的配信そのものの CSP・通信制限はブラウザ側で許可する必要があり、静的 HTML だけでは解除できません。

エラー表示は HTTP 403（接続拒否）、429（利用制限）、5xx、タイムアウト、オフライン、CSP 違反を区別します。ブラウザが理由を返さない `TypeError` は「原因未確定」とし、CORS と断定しません。画面内の「通信エラーの詳細」にサービス・接続先・HTTP 状態・接続方式・表示元を出し、コンソールにも `[晴れキャン API]` として記録します。HTTP 200 で一致候補がない場合だけ「通信は成功・0件」と表示します。空結果は24時間キャッシュしません。

「亀山湖オートキャンプ場」は Nominatim が別の湖の施設を返すことを確認しました。施設名を照合して無関係な候補を除外します。指定施設は[なっぷの公開施設情報](https://www.nap-camp.com/chiba/11955)の `Campground` JSON-LD で名称・住所・座標を確認した補足候補を使います（2026-10-31確認、千葉県君津市折木沢湯の川1306、35.215901 / 140.106592）。ライブ検索結果と誤認しないよう画面に出典を表示します。API 通信失敗を補足候補で隠しません。補足候補もユーザー確認後にのみ登録し、予報は Open-Meteo から取得します。営業可否を保証する情報ではありません。

ブラウザでのネットワーク回帰確認は、開発サーバー起動後に実行します。

```sh
npm run dev
# 別のターミナルで（システムのChromiumを使う環境）
node tests/network-preview.cjs
```

この確認は外部直接通信を禁止する `connect-src 'self'` 条件を付け、実 API 経由で初期3施設・亀山湖の検索・登録・4施設の予報・再読み込み後の保持を検証します。検索0件は実 API、403 はテスト応答で別々に確認します。`CAMP_PREVIEW_URL` でプレビューの URL を指定できます。

## 日程選択・削除・追加方法

- 各カードの「削除」から確認ダイアログを開き、「削除する」で確定します。キャンセルでは変更しません。初期施設も削除でき、最後の1施設を削除した後も再読み込みで復活しません。0件時は追加を促す案内を表示します。
- 追加方法は「キャンプ場名」「住所検索」「地図で指定」の3つです。住所検索の候補または地図上でクリック・タップした地点を選び、キャンプ場名と場所を確認して登録します。地図指定地点の住所は座標で表示し、実住所を推測しません。
- 地図はLeafletとOpenStreetMapのタイルを使用します。`tile.openstreetmap.org` への画像取得が必要です。地図画像の取得失敗時には案内を出し、施設名・住所検索は使い続けられます。
- 変更や削除の保存に失敗した場合はエラーを表示し、登録済みデータを変更しません。

開発プレビューを起動した状態で `CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:trip` を実行すると、日程別表示・順位・予報範囲外・旧データ移行・削除キャンセル・0件保持・住所と地図からの追加・スマートフォン幅をブラウザで検証できます。この自動テストの予報とタイルはテスト応答です。実API・実地図での動作確認とは区別します。

## スマートフォンの日程入力

600px以下では開始日・泊数を1列、各入力を幅100%にします。Gridの列・ラベル・入力の `min-width: 0` とSafariの日付入力の内在幅対策を適用しています。`npm run test:layout` はChromiumとWebKitで320〜600pxの縦配置、1024pxの横配置、重なりと横スクロールがないことを確認します。Playwrightブラウザと実行ライブラリが必要です。`CHROMIUM_EXECUTABLE_PATH` / `WEBKIT_EXECUTABLE_PATH` で既存のブラウザ実行ファイルを指定できます。

## 気象庁の参考予報（Vercel）

各カードの「気象庁の参考予報」を開くと、実際の予報区域名・選択日の天気・発表済み降水確率・発表日時を表示します。Open-Meteoは主予報のままで、撤収日優先のランキングは変更しません。APIキーや有料サービスの設定は不要です。Vercelの既存ビルド設定のまま `api/jma-area.js` / `api/jma-forecast.js` が動作します。静的GitHub Pages単体ではこの参考機能のサーバーが使えません。

短期の降水確率は日本時間の6時間ごと、週間は日単位の気象庁発表値をそのまま表示します。キャンプ場のピンポイント予報ではありません。Open-Meteoはモデル更新日時ではなく「データ取得日時」、気象庁は「予報発表日時」と「データ取得日時」を分けて表示します。

[取得方法・利用規約・区域判定・更新頻度・キャッシュ・制約](docs/JMA-REFERENCE.md)を参照してください。`npm test`、`npm run test:jma`、実APIのブラウザ確認 `node tests/jma-browser.js --real` を用意しています。テスト用予報は `tests/` に隔離しています。アクセス比較機能の `feat/access-comparison` ブランチはこの変更に含めません。

## キャンプ場の検索と地図調整

キャンプ場名検索が正常に完了して0件だったときだけ、住所検索・地図指定への案内を表示します。通信エラーは別の表示です。住所・地図内の検索は、全角数字・全角ハイフン・全角スペースを正規化します。漢数字や地名の長音符等は変換しません。

住所の候補を選んで「地図で位置を調整」を押すと、その座標を中心にピンを表示します。タップ・ドラッグの後に「この位置を確定」、続いて「キャンプ場を登録」を押します。地図の移動や候補選択だけでは登録しません。元の候補座標と調整後の位置を区別し、住所検索へ戻っても入力・選択候補・入力した施設名・地図で確定した位置を保持します。未確定の調整がある場合は、そのまま元の座標で登録できないようにしています。

「地図で指定」からも住所・地名を検索できます。複数候補は選択式で、検索0件・通信エラーでも既存のピンは動かしません。地図から登録する位置は `map-pin` として最終座標を保存し、元候補のOSM IDと混同しません。元の住所は「参考住所」と表示し、移動後の正確な住所と扱いません。既存のキャンプ場保存キーと形式は変更しません。

検索は既存のNominatimを使い、入力中の自動検索は行いません。同じブラウザの検索間隔は既存の1.1秒以上、成功結果はキャッシュを再利用します。住所検索と地図内検索も同じ制御を共有します。[Nominatim利用ポリシー](https://operations.osmfoundation.org/policies/nominatim/)とOpenStreetMapの出典表示を維持します。サービスに未登録の番地等は検索結果が0件になる場合があります。新規の有料APIや課金設定は不要です。

`npm run test:registration` はChromium/WebKitで0件・通信エラー・全角/半角・地図のタップ/ドラッグ・戻る・確定座標の保存/再読み込み・320〜1024px表示を検証します。Chromiumではネイティブのタッチドラッグも確認します。`node tests/registration-live.js` は実際のNominatim・OSM地図・Open-Meteo・気象庁を使って操作を確認します。ブラウザの登録はテスト用コンテキストのlocalStorage内に限定し、テスト用の応答データを本番アプリへ組み込みません。
